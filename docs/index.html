Print from the terminal.
Or just ask your agent to.

uprint is a Universal Print CLI for Windows. It prints silently, to the printer you actually meant, and every command can speak a versioned JSON envelope, so a human can run it and an AI agent can drive it.

INSTALL · WORKS TODAY 
git clone https://github.com/kalebcole/uprint-cli.git
cd uprint-cli
npm ci && npm run build
node bin/uprint.js setup

Windows, Node.js 20 or newer. No package-manager step yet. An npm install -g route arrives with the TypeScript port.

BEFORE Start-Process -Verb Print

Acrobat opens and stays open. The job goes to whatever printer Windows had selected. Nothing tells you whether it worked.

AFTER uprint print report.pdf

Nothing opens. The printer you named gets it. You get back where it went, which engine sent it, and whether it is waiting on your badge.

§ 1

Why this exists

I couldn't print from my dev box. Every time I needed a document printed, whether a form, a license or a receipt, I had to walk over to a coworker's desk and ask them to print it for me.

The printer was right there. On the network. Connected via Universal Print. But the tooling to actually send a job to it from the command line? Didn't exist.

Start-Process -Verb Print opened Adobe Acrobat, left it running, printed to the wrong printer, and gave no feedback. I couldn't even tell if my job was submitted, let alone whether it was waiting for my badge tap at the printer.

So I built uprint. A CLI that prints silently, targets the right printer, and speaks JSON so AI agents can use it too.

What that actually fixed

Silent
SumatraPDF runs hidden and exits. No window, no popup, no process left behind.
Targeted
The printer name is passed explicitly to the engine, not inherited from whatever Windows had selected.
Legible
Every command reports where the job went, which engine sent it, and whether it is waiting on a badge.
Fallback
SumatraPDF, then Acrobat, then the OS print verb. The envelope names which one ran.
§ 2

The part built for agents

Most CLIs make an agent scrape human text and guess. uprint hands it a contract instead: one envelope shape, every command, every time, success or failure.

SUCCESS · uprint status --json 
{
  "version": 1,
  "command": "status",
  "timestamp": "2026-01-15T09:30:00.0000000-08:00",
  "success": true,
  "data": {
    "name": "Office-Printer-1",
    "status": "Normal",
    "driver": "Universal Print Class Driver",
    "port": "UPPORT:",
    "pendingJobs": 0,
    "isUP": true
  }
}
FAILURE · error replaces data 
{
  "version": 1,
  "command": "status",
  "timestamp": "2026-01-15T09:31:12.0000000-08:00",
  "success": false,
  "error": {
    "code": "PRINTER_NOT_FOUND",
    "message": "Specified printer was not found",
    "suggestion": "Run 'uprint printers' to list available printers"
  }
}

Never both

An envelope carries data or error, never the two together. Branch on success and you are done.

Errors suggest

Every error carries a suggestion naming the next command to run, so an agent can recover instead of stalling.

Warnings ride along

An optional warnings array sits beside a success, so a job can succeed and report that it is waiting on a badge.

Success is the signal

Branch on success, not the exit code. Every result exits 0 — a handled error and an unknown command alike. The envelope carries the outcome.

NOT SHIPPED YET

uprint skill install

One command to register uprint as a tool your coding agent already knows how to call. No prompt engineering, no wrapper script. It is on the roadmap and does not exist yet. Until it lands, point your agent at SKILL.md in the repo, which documents the same surface by hand.

§ 3

Command reference

Everything the CLI accepts today. Nothing here is aspirational.

uprint commands, what they do, and their flags
CommandWhat it doesFlags
uprint setup Interactive printer discovery. Lists what is available and saves your default. Run this first. none
uprint printers List available printers. --universal-only -u
uprint status Printer state, driver, port, pending job count, and whether it is a Universal Print device. none
uprint print <file> Print a file. Resolves the path, selects a print engine, and reports which one it used. --copies N --duplex --color --mono
uprint queue List jobs currently in the print queue. none
uprint queue cancel <id> Cancel a single job by its numeric id. none
uprint queue cancel --all Cancel every job on the target printer. --all
uprint health Composite diagnostic across spooler, printer state, queue backlog, and the Universal Print driver. none
uprint config set <key> <value> Write a config value. Booleans and integers are coerced from strings. none
uprint config get Print the whole configuration. A key argument is accepted but currently ignored. It always returns the full config. Known bug. none

Global flags

--human
Opt out of JSON and print readable tables. --json is accepted but now a no-op.
--printer <name>
Override the configured default for one invocation.
--help
Usage summary.

Exit codes

0
Success — and also a handled error, which reports itself in the envelope. Check success.
1
Unknown command.
3
Invalid input, such as a missing file argument.

Configuration

Stored at %USERPROFILE%\.uprint\config.json

defaultPrinter
Target used when --printer is absent.
jsonOutput
Defaults to true. Set it to false to make every command behave as if --human were passed.
autoWake
Default true.
timeout
Default 10000.
§ 4

Get it running

  1. 01

    Clone and set up

    git clone https://github.com/kalebcole/uprint-cli.git
cd uprint-cli
npm ci && npm run build
node bin/uprint.js setup

    setup lists the printers it can see and saves the one you choose. Until you run it, every other command stops and tells you to.

  2. 02

    Print something

    node bin/uprint.js print report.pdf --human

    If the target is a Universal Print device, the job waits in the cloud until you badge at the printer. The output says so.

  3. 03

    Hand it to an agent

    node bin/uprint.js print report.pdf

    Point your agent at skills/uprint/SKILL.md in the repo for the documented surface, and let it branch on success.

Requirements

  • Windows 10 or 11 with Node.js 20 or newer
  • A printer the machine can already see, Universal Print or otherwise
  • Optional: SumatraPDF in tools\ for fully silent printing. Without it, uprint falls back to Acrobat, then the OS print verb.
§ 5

Known limits

Printing touches hardware, a cloud queue and a badge reader. Here is what this tool does not yet handle, stated up front rather than discovered later.

  • Submitted is not printed. A successful envelope means the job reached the spooler or the cloud queue. It is not proof that paper came out. The print engine's exit code is not yet checked.
  • Print options are recorded, not yet enforced. --duplex, --color and --mono are echoed back in the envelope, but the underlying engine does not apply them.
  • config get ignores its key. It returns the entire config regardless of what you ask for.
  • Windows only. It is built on the Windows print subsystem and PowerShell's printer cmdlets. There is no macOS or Linux path.

All four are tracked in the issue tracker. If one of them is in your way, say so there.
